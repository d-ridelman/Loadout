# Loadout — концепт

> Что загружено в твоих агентов: плагины, MCP, скилы, хуки, агенты, правила. Один экран на все клиенты.

Статус: концепт. Кода приложения нет, есть этот документ и кликабельный макет `mockup/index.html`.
Метки в таблицах: **[проверено]** — видел на этой машине: имена файлов, каталогов и ключей, плюс по одной записи без секретов (`installed_plugins.json`, шапка одного `SKILL.md`); значения из конфигов с токенами не читал; **[гипотеза]** — не проверено, в M0 надо подтвердить на фикстурах.

## 1. Боль и цель

Сущности агента размазаны по пяти клиентам и десяткам файлов в разных форматах (JSON, TOML, YAML, каталоги с `SKILL.md`). Ответить на «где стоит glidehand и включён ли он в Codex?» можно только руками.

Цель: за один взгляд видеть, **что где установлено, включено и сломано**, и безопасно этим управлять.

Не цели (v1):
- Облачные коннекторы claude.ai / ChatGPT. Их список лежит на сервере, с диска не читается. Покажем плашку «только в приложении» и ссылку, управлять не обещаем.
- Установка плагинов из маркетплейсов. Это дело самих клиентов.
- macOS и Linux. Пути абстрагируем сразу, но тестируем и собираем Windows 11. WSL-проекты (в `config.toml` Codex есть `\\wsl.localhost\...`) — после v1.

Важные наблюдения, из которых вырос дизайн:
1. **Один пакет — несколько клиентов.** Плагин `ai-playbook` несёт сразу `.claude-plugin`, `.codex-plugin` и `.antigravity-plugin` **[проверено]**. Значит, одна логическая сущность живёт в клиентах отдельными экземплярами. Главный экран строим как матрицу «сущность × клиенты».
   **Тип у экземпляров может различаться:** glidehand в Claude Code включён как плагин (`enabledPlugins`), а в Codex и Antigravity подключён как MCP-сервер **[проверено проверяющим по именам ключей]**. Поэтому `kind` — свойство экземпляра, а `logicalKey` строки группирует по имени между типами. Правила сопоставления («плагин X» ↔ «MCP X») — задача M0.
2. **Дубли и дрейф уже есть.** В `installed_plugins.json` `skill-creator@claude-plugins-official` записан дважды: область `user` и область `project` (с `projectPath`) **[проверено]**. Поле `version` в двух записях разное (короткие git-хеши) — видел на этой машине. Отдельно `skill-creator` стоит и в `~/.codex/skills`, и в `~/.codex/skills/.system`.
3. **Свалка бэкапов.** В `~/.codex` и `~/.gemini/config` лежит по ~20 чужих `*.bak`. Мы не добавляем туда ничего, у нас своё хранилище.
4. **Секреты рядом с настройками.** `~/.claude.json` содержит ключ `oauthAccount` **[проверено, имя ключа]**. Что MCP-конфиги держат токены в `env` — **[гипотеза]**, значения я не читал. Маскирование — требование, а не опция.

## 3. Единая модель

```
Entity {
  id            стабильный хеш(client, scope, kind, name, source.file)
  logicalKey    ключ для строки матрицы: имя пакета/сервера, нормализованное
  kind          plugin | mcp | skill | hook | agent | command | rule | marketplace | memory | connector
                (свойство экземпляра: glidehand — plugin в одном клиенте и mcp в другом)
  client        claude-code | claude-desktop | codex | antigravity | deepseek
  scope         user | project(путь) | plugin(origin) | builtin | cloud
  origin        { plugin?, marketplace?, file, pointer }   // pointer: JSON Pointer / TOML key / строка
  state         on | off | broken | shadowed | stale | unknown
  version       строка | gitCommitSha
  capabilities  { toggle, remove, edit, copyTo[] }          // что разрешено делать с этим экземпляром
  usage?        { lastSeen, count }                         // если клиент это пишет
  fingerprint   хеш содержимого (SKILL.md, манифест) для поиска «та же вещь в другом клиенте»
  masked        поля, которые скрыты
}
```

Состояния:

| state | смысл | как узнаём |
|---|---|---|
| `on` / `off` | включено / выключено клиентом | `enabledPlugins`, механизмы выключения MCP из §2, `[plugins.*] enabled`, … |
| `broken` | команда MCP не найдена, `installPath` не существует, хук ссылается на отсутствующий скрипт | `which` / `exists`, без запуска |
| `shadowed` | одноимённая сущность перекрыта другой областью | порядок слияния конкретного клиента |
| `stale` | версия/хеш расходятся с другими клиентами или маркетплейсом | сравнение `fingerprint`/`version` |
| `unknown` | формат не распознан | адаптер сохраняет сырой фрагмент и **не трогает** |

Правило адаптеров: **неизвестные ключи сохраняем при записи как есть.** Форматы неофициальные и меняются, поэтому у каждого адаптера есть `schemaVersion`, а на любую неожиданность он отвечает `unknown`, а не падением.

## 4. Экраны

В макете (`mockup/index.html`) работают пункты 1–5 и 7; Журнал (6) — заглушка.

1. **Матрица (главный экран).** Строки — логические сущности, столбцы — клиенты, в ячейке — глиф состояния. Видно сразу: glidehand есть как плагин в Claude Code и как MCP в Codex и Antigravity; есть ли он в DeepSeek, надо проверить в M0 (упоминания лежат в `cordis.patch.yml`, структуру файла я не разобрал). Фильтры по типу и состоянию, поиск, группировка по происхождению (плагин/маркетплейс). Строка раскрывается в экземпляры по областям.
2. **Радар.** Обзор: кольцо на клиент с числом сущностей по типам, пульс «здоров / есть проблемы», список проблем справа. Это «HUD»-экран, но не просто украшение: клик по сектору ведёт в матрицу с готовым фильтром.
3. **Инспектор (правая панель).** Источник (файл и строка/путь ключа), сырой фрагмент с маскированием, что произойдёт при изменении (diff до записи), кнопки «открыть в редакторе», «показать в папке», «копировать путь».
4. **Хуки: конвейер.** Жизненный цикл `SessionStart → UserPromptSubmit → PreToolUse → PermissionRequest → PostToolUse → Stop` по дорожкам клиентов; на каждом шаге — хуки в порядке выполнения, с matcher и источником (user / project / плагин). События разных клиентов сопоставляются по таблице соответствия, непарные помечаются.

   Таблица соответствия событий (что известно сейчас):

   | Клиент | События | Статус |
   |---|---|---|
   | Codex | `SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, SubagentStart, SubagentStop, Stop, Interrupt` | проверено (`~/.codex/hooks.json`) |
   | Claude Code | в `settings.json` сейчас используются `SessionStart, PreToolUse, PostToolUse`; полный набор событий клиента не проверен | частично |
   | Antigravity | схема `~/.gemini/config/hooks.json` не разобрана | гипотеза |
   | DeepSeek | схема `~/.dsh/ctxkit-hooks.json` не разобрана | гипотеза |
   | Claude Desktop (чат) | хуков на диске не найдено | не найдено |

   Шкала в макете (дорожки, штриховка «нет события») — иллюстрация формы, не данные.
5. **Доктор.** Автоматические находки: битые пути, дубли, перекрытия, расхождение версий, MCP с секретом в открытом виде, осиротевшие маркетплейсы, свалка `*.bak`. Каждая находка — «что, почему плохо, что предлагаем» и ссылка на сущность.
6. **Журнал.** Снимки состояния и diff «что изменилось с прошлого раза», откат. Появляется с M3 (в макете — заглушка).
7. **Палитра команд (`Ctrl+K`).** Переход к сущности, смена фильтра, действия над выбранным. Всё доступно с клавиатуры: `j/k` — строки, `h/l` — клиенты, `/` — поиск, `Space` — переключить (когда включена запись), `Enter` — инспектор, `?` — шпаргалка.

### Профили (M4)
Именованные наборы «что должно быть включено» (например, «рабочий Visiology», «реверс»). Применение профиля — это пакет записей через тот же безопасный конвейер, одним предпросмотром.

## 5. Безопасность записи

Читать можно всё, писать — по уровням. Уровень включается в настройках, по умолчанию выключен.

| Уровень | Что разрешено | Версия |
|---|---|---|
| R0 | только чтение | v1 / M1 |
| R1 | включить / выключить | M3 |
| R2 | править, копировать между клиентами, переносить в корзину | M4 |

Конвейер любой записи:
1. **План**: ядро строит набор правок и diff, ничего не пишет.
2. **Предпросмотр**: UI показывает diff по каждому файлу, пользователь подтверждает.
3. **Клиент запущен?** Проверяем процесс (Claude Code, Codex, Antigravity, dsh). Если да — предупреждение, что клиент может перезаписать файл своим состоянием, и предложение подождать.
4. **Оптимистичная блокировка**: хеш файла до плана и перед записью. Не совпал — план перестроить.
5. **Бэкап** в `%APPDATA%\Loadout\backups\<время>\` с манифестом (исходный путь, SHA-256). Чужие `.bak` не создаём.
6. **Атомарная запись**: временный файл рядом + переименование. TOML правим через `toml_edit` (сохраняет комментарии и порядок), JSON — точечной правкой по CST, а не перезаписью всего файла.
7. **Проверка**: перечитать и убедиться, что результат равен «исходник + план», остальное не изменилось.
8. **Откат** одной кнопкой из журнала. Удаление = перенос в корзину Loadout, не `rm`.

Секреты:
- Ядро по умолчанию отдаёт значения **замаскированными** (ключи `token|key|secret|password|authorization|credential|oauth`, весь блок `env` у MCP, также `http_headers` у MCP в Codex; файлы из строки «Секреты других клиентов» в §2 не читаются вообще).
- «Показать» — по удержанию, значение живёт в UI только пока удержано.
- Ни телеметрии, ни сети. Приложение работает офлайн, запросов к маркетплейсам не делает.

Запуск чужих команд:
- Проверка MCP («поднять и спросить tools/list») **выполняет команду из конфига**, поэтому только по явной кнопке на конкретном сервере, с таймаутом 5 с и в отдельном процессе. Массовой проверки нет.

## 6. Архитектура

```
┌────────────────────────── Electron ──────────────────────────┐
│ renderer (React + TypeScript + Vite)   — только UI            │
│   ▲ typed IPC (contextBridge, allow-list)                     │
│ main  — окна, меню, трей, файловые диалоги, сторож процессов  │
│   ▲ stdio: JSON-RPC, строки через \n                          │
└───┼───────────────────────────────────────────────────────────┘
    ▼
loadoutd (Rust, sidecar)  ──  loadout-core (библиотека)
   adapters/{claude_code, claude_desktop, codex, antigravity, deepseek}
   model · scan · diff · plan · backup · mask · watch (notify)
```

**Граница Rust ↔ Electron: sidecar по stdio, а не napi-rs.** Причины: падение парсера не роняет окно; не надо пересобирать нативный модуль под каждую версию Electron; тот же бинарь работает как CLI (`loadout scan --json`) и в тестах. Цена — сериализация, но объёмы здесь сотни записей, это не узкое место.

Выбор технологий (не из требований, а из удобства):
- Renderer: React + TypeScript, `@tanstack/react-virtual` для списков, Zustand для состояния. Ничего тяжелее.
- Rust: `serde`/`serde_json`, `toml_edit`, `serde_yaml` (YAML в v1 только чтение), `notify`, `rayon`, `sha2`, `jsonc-parser`.
- Третий язык не нужен. Python/Go не добавляем.
- Упаковка: `electron-builder`, NSIS-установщик для Windows. Sidecar лежит рядом, путь зашит, не из PATH.

Безопасность Electron: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, строгий CSP без `unsafe-eval`, никаких удалённых URL, IPC только по allow-list, имена файлов из UI проверяются ядром (запись только в известные пути адаптеров).

Макет структуры репозитория:
```
Loadout/
  crates/loadout-core/     модель, адаптеры, диф, бэкап
  crates/loadoutd/         sidecar (JSON-RPC)
  app/{main,preload,renderer}/
  fixtures/                обезличенные снимки конфигов с этой машины
  docs/CONCEPT.md
  mockup/index.html
```

## 7. Производительность

Цели, **не измерены** (замерить в M1):
- холодный скан всех клиентов — меньше 500 мс на этой машине;
- простой — 0 % CPU, окно в фоне не перерисовывается;
- ОЗУ в простое — до 150 МБ.

Как достигаем:
- Скан параллельный (`rayon`), `SKILL.md` читаем только голову (до 4 КБ) для frontmatter.
- Кеш «путь + mtime + размер → разобранная сущность», перечитываем только изменившееся.
- Сторож `notify` только на известные конфиги и каталоги скилов. **Каталоги `plugins/cache`, `sessions`, `transcripts`, `projects`, `*.sqlite` не слушаем** — они огромные и шумные. Дебаунс 200 мс.
- Виртуализация списков, иначе матрица на тысячу строк тормозит.
- Рендер матрицы без анимации на каждую ячейку.

| состояния | зелёный `#50fa7b` (on), оранжевый `#ffb86c` (stale), фиолетовый `#bd93f9` (shadowed), красный `#ff5555` (broken; в макете глиф светлее, `#ff6e6e`: на панели 5,80, в выделенной ячейке 4,76, при наведении 5,13; в нижней точке пульса с `opacity .7` — 3,04–3,50, это значок с подписью, для него порог 3:1), серый (off), голубой (cloud) |

**Контраст посчитан** (WCAG, формула из спецификации): классический «comment» `#6272a4` на `#282a36` даёт **3,03:1** — не проходит AA для текста (нужно 4,5). Для текста берём `#9aa5ce` (5,86:1). `#6272a4` годится только для рамок и декора. Красный `#ff5555` на фоне — 4,53:1, проходит впритык, поэтому красный всегда с глифом и подписью.

HUD-эффекты — только то, что дёшево:
- уголки-скобки на панелях (псевдоэлементы), тонкая сетка и лёгкие «сканлайны» (градиент, прозрачность ~3 %);
- свечение акцентов через `box-shadow` / `text-shadow`;
- радар с вращающимся лучом (`conic-gradient` + `transform: rotate`, идёт на композиторе, не вызывает layout);
- пульс состояния (`opacity`), короткая «загрузочная» анимация при запуске (до 600 мс), счётчики с плавным набором чисел;
- никакого WebGL/canvas в v1. Это вопрос расхода GPU на общей машине.

Управление эффектами: настройка **FX: выкл / лёгкие / полные**. При `prefers-reduced-motion` включается «выкл» сам. Если окно теряет фокус или свёрнуто, анимации ставятся на паузу.

Доступность: состояние не только цветом, но и формой глифа (`●` вкл, `○` выкл, `◐` расхождение, `◒` перекрыто, `☁` только облако, `✕` сломано, `–` нет); на фоне панели не используем `#44475a` как цвет текста или глифа (контраст около 1,7), для «нет» берём `#6272a4` только как декор рядом с подписью; видимое кольцо фокуса; матрица — `role="grid"`; полная работа с клавиатуры.

Шрифты: JetBrains Mono для данных и Inter для текста, **вшиты в сборку**, без CDN (офлайн).

## 9. Тесты

- Rust: у каждого адаптера golden-тесты на обезличенных фикстурах (`fixtures/`), property-тест «записали → перечитали → равно исходнику плюс правка, неизвестные ключи целы».
- Тест маскирования: ни одно значение из списка секретных ключей не доходит до JSON-RPC-ответа.
- Electron: Playwright (`_electron`) — запуск, матрица видна, клавиатурная навигация, `prefers-reduced-motion`.
- Контраст: автотест на токены палитры (пороги 4,5 / 3).

## 11. Риски и открытые вопросы

- **Форматы неофициальные.** Любой апдейт клиента может их поменять. Смягчение: версия адаптера, `unknown` вместо падения, golden-тесты.
- **Клиент перезапишет наш файл.** Для этого проверка процесса и оптимистичная блокировка; полностью исключить гонку нельзя.
- **DeepSeek harness:** где именно живут его MCP и плагины, не подтверждено. До M0 адаптер показывает только скилы, хуки и инструкции.
- **ChatGPT desktop:** не найден, см. §2.
- **`antigravity/mcp/*/*.json`:** возможно кеш схем, а не конфиг. Не пишем в него никогда.
- **Копирование сущности между клиентами** (M4) требует трансляции форматов (например, MCP из JSON в TOML). Для хуков семантика событий различается, переносим только совпадающие события и честно показываем потери.

## 12. Что осознанно не сделано в концепте

`shortcut:` нет `npm install`, нет Electron-скелета и cargo-проекта — это концепт, код начинается с M0. Метки «гипотеза» из §2 не проверены чтением значений секретных конфигов: имена файлов, секций и ключей смотрел, токены не трогал. Проза документа не прогонялась через humanizer. В макете имена сущностей реальные с этой машины, а состояния («сломано», «секрет открыт», «отстаёт») подобраны для демонстрации. Известные недоделки макета: нет ловушки фокуса в палитре и `aria-activedescendant` у её поля; часть статических значений вставляется без `esc` (данные не приходят снаружи).
