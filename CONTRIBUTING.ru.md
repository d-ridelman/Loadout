# Как участвовать в разработке Loadout

[English](CONTRIBUTING.md) · [Русский](CONTRIBUTING.ru.md)

Loadout пишет в конфиги чужих программ, поэтому главное требование к правкам: не потерять и не раскрыть данные пользователя. Прочитайте эту страницу до того, как открывать pull request.

## Подготовка

Нужны: Windows 11 x64 (Windows 10 не проверялась), Rust 1.91 или новее с набором MSVC (нижняя граница от `notify-types` в `Cargo.lock`), Node.js 22.12+, 24 или 26+ (23 и 25 vitest не поддерживает), `git`.

```bash
git clone https://github.com/d-ridelman/Loadout.git
cd Loadout
cargo build --release
cd app && npm ci
```

Если после `npm ci` нет `app/node_modules/electron/dist/electron.exe` (npm не запустил скрипты установки пакетов), скачайте его: `node node_modules/electron/install.js`.

`npm run dev` открывает окно в режиме разработки. Оно читает ваши настоящие конфиги и хранит данные в `%APPDATA%\loadout-app`, как установленная копия. Чтобы работать на копии, задайте `LOADOUT_HOME` (домашний каталог с конфигами клиентов) и `LOADOUT_USER_DATA` (папка данных окна); в установленной сборке эти переменные не действуют.

## Перед отправкой

Быстрый путь: `node tools/verify.mjs` запускает только те проверки, которые нужны изменённым файлам, от дешёвых к дорогим, и останавливается на первой красной (`--dry` показывает план, `--all` запускает всё, `--release` добавляет снимки, установщик и его проверку). Проверки и правила лежат в `.claude/verify.json`, тесты к ним — в `tools/verify-rules.test.mjs`.

Всё это должно проходить:

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cd app
npm run typecheck
npx vitest run
npm run e2e          # собирает ядро, context-toolkit.exe и окно, гоняет настоящее приложение на фикстурах (около 2 минут)
```

У `crates/context-toolkit` есть ещё `node crates/context-toolkit/tests/guard.test.mjs` (сначала `cargo build --release`). Проверка упакованной сборки: `npm run pack`, затем `npm run pack:check` (она читает ваши настоящие конфиги, только на чтение, уровень R0).

e2e открывает окна приложения и снимает их, поэтому запускайте его, когда машина не занята. Снимки пишутся во временный каталог, путь к нему прогон печатает в конце, так что рабочее дерево остаётся чистым. `E2E_UPDATE_SHOTS=1 npm run e2e` (или `node tools/verify.mjs --release`) обновляет закоммиченные снимки в `state/`, когда окно действительно изменилось. После записи конфига ни одна пауза не ждёт сторожа файлов (план сам читает диск). Оставшиеся короткие паузы намеренные: раздел или раскладка устанавливаются перед снимком, замером раскладки или доступности и проверкой английского текста; отрицательная проверка даёт неверному состоянию время проявиться. Новое ожидание ждёт условия, которое показывает приложение.

## Правила, которые важны

- **Тесты не пишут в настоящий профиль.** Тесты и сценарии e2e работают на копиях `fixtures/` во временном каталоге (`LOADOUT_HOME`, `LOADOUT_USER_DATA`). Настоящие конфиги разработчика меняться не должны: e2e сверяет хеши настоящих файлов до и после.
- **Запись идёт через конвейер** из [docs/CONCEPT.md](docs/CONCEPT.md) §5 (на английском: [docs/CONCEPT.en.md](docs/CONCEPT.en.md)): план, предпросмотр, хеш-блокировка, бэкап, атомарная запись, сверка, журнал, откат. У новой операции записи есть уровень (R1 для простых флагов, R2 для остального), откат и тест отката (файл возвращается побайтово).
- **Правим точечно.** JSON по AST, TOML через `toml_edit`, YAML по строкам: меняется только затронутое значение, комментарии, порядок ключей и переводы строк остаются.
- **Секреты остаются в ядре.** Значения env и заголовков не должны попадать в план, запись журнала, текст ошибки и окно. Имена ключей можно, значения нельзя. Новое поле, способное нести значение, получает тест маскирования.
- **Правка логики идёт с тестом**, который падает до правки и проходит после. Лишний код, о котором не просили, повод вернуть правку.
- **Снимки для README** (`docs/screenshots/`) делает `npm run docs-shots` в `app/`: окно 1920×1080 на фикстурах, русский и английский. Скрипт проверяет, что в окне нет имени пользователя и пути настоящего домашнего каталога, но каждый снимок перед коммитом всё равно посмотрите глазами. Обновляйте их, когда интерфейс заметно меняется.
- **Уязвимости** не обсуждаются в issue: см. [SECURITY.ru.md](SECURITY.ru.md).
- GitHub Actions и Dependabot не настроены сознательно.

## Pull request

- Одна тема на один pull request, короткое описание, что меняется и зачем, и что вы запускали.
- Сообщения коммитов: повелительное или описательное, история в основном на русском, английский тоже подойдёт.
- Правка, которая трогает путь записи или маскирование, сверяется с заметками в [docs/CONCEPT.md](docs/CONCEPT.md) §10.5 (аудиты и известные пределы).

## Сообщить о проблеме

Откройте issue: клиент и его версия, что вы делали, что ожидали и что получилось. Конфиги не вставляйте: в них могут быть токены. Достаточно имён ключей и записей.
