# Исследование расхода токенов, лимитов и эффективности AI-агентов

<p><a href="RESEARCH.md">English</a> | <strong>Русский</strong></p>

В документе сведены три проверки: схема роутинга из X (`@0xCodila`, 10-11.11.2026) и документации Anthropic, разбор идеи «Rust MCP + PostToolUse-демон» из обсуждения с Gemini и замер 30 реальных сессий Claude Code (`26 256` ходов ассистента через [`scripts/audit-sessions.mjs`](../scripts/audit-sessions.mjs)).

## Где работает экономия

`ctxkit` написан на Rust только ради нативного exe со стартом `9-14 ms` без поднятия Node или Python на каждый вызов. Сама экономия относится к любым проектам, включая TypeScript/JS, Python и Go: в измеренных 30 сессиях основная потеря контекста пришлась на `2 793` shell-инспекций и `1 363` полных чтения файлов размером до `66.6 KB`, а также `2 197` запусков `tsc`, `npm test`, `node --test`, `pytest` и сборок.

## Выводы из X (`@0xCodila`) и документации Anthropic

Посты `@0xCodila` и руководства Anthropic (`advisor`, `sub-agents`, `model-config`) описывают 4-модельную команду со снижением расхода до `~3.4x` по сравнению с работой флагманской модели на каждом шаге.

| Роль | Модель | Инструменты и задача | Зачем нужна в схеме |
|---|---|---|---|
| Основная сессия | `Sonnet` (`sonnet`) | Пишет код, правит файлы, запускает тесты | Основной объём ходов на быстрой средней модели |
| Советник | `Fable` (`advisorModel: fable`) | Только отвечает на консультации | Вызывается около 3 раз за задачу: план, повтор ошибки, финал |
| Поиск и чтение | `Haiku` (`Explore`) | `Read, Grep, Glob` (read-only) | Удерживает большой поиск вне кэша основной сессии |
| Финальный ревьюер | `Opus` (`checker`) | `Read, Grep, Glob, Bash` (read-only) | Проверяет `git diff`, прогоняет тесты и краевые случаи перед сдачей |

При проверке документации и практики выявились четыре технические детали, без которых роутинг ломается:

1. В тестах Anthropic без явной инструкции в `CLAUDE.md` (вызывать advisor перед фиксацией подхода, при повторе той же ошибки дважды и перед финалом) Sonnet обращался к advisor `0 раз из 198`.
2. Снижение `effortLevel` у основной модели ниже стандартного (`high`) резко сокращает число вызовов advisor, поэтому в связке с `/advisor` лучше оставлять `high`.
3. Встроенный субагент `Explore` игнорирует переменную `CLAUDE_CODE_SUBAGENT_MODEL` и работает на основной модели. Нужно явно создать `~/.claude/agents/Explore.md` с `name: Explore` и `model: haiku`.
4. Корневой `CLAUDE.md` стоит держать короче 200 строк (~4-6 KB), вынося правила подпапок в `.claude/rules/*.md` с полем `paths:`. Исключения из запрета, написанные в том же предложении, повышали соблюдение правил в замерах Anthropic с `~1/10` до `~9/10`.

Для оценки роли советника в статье приводились бенчмарки `Fable 5.2`: `Remote Labor Index` `41.3%` против `21.3%` у `Opus 5.5`, `20.8%` у `GPT-6 Astra` и `17.9%` у `Fable 5.1`; `BenchCAD 2.1` `83.5` против `65.3`; `OSWorld 2.1` `89.3%`. При цене `$8` / `$40` за 1M input/output токенов гонять такую модель на grep и чтение конфигов невыгодно, зато как редкий консультант она быстро окупается.

## Проверка идей из обсуждения с Gemini

В исходном обсуждении предлагалось отобрать у агента встроенные `Read`/`Bash` в пользу кастомного AST-MCP (`tree-sitter`/`syn`), повесить на `PostToolUse` демон с `cargo check` + `clippy --fix` + локальной LLM после каждой записи файла и запретить обычный текст в ответах через `CLAUDE.md`. Проверка показала смешанный результат.

| Идея из обсуждения | Решение | Основание |
|---|---|---|
| Сжатие `cargo check --message-format=json` и тестовых логов | Принято (`ctxkit check`) | Срезает `11.2%` мусора `tool_result` (реально ~6-10% общей экономии на разных стеках и до 12-15% при ошибках компиляции) |
| Неизменный префикс промпта под Prompt Caching | Принято | Инструмент `/advisor` сохраняет префиксный кэш, а смена модели посреди сессии его ломает |
| Срез `rendered.lines().take(4)` из примера кода | Исправлено | Суть ошибки Rust вроде `expected A, found B` часто уходит ниже 4-й строки `rendered`, поэтому `check.rs` читает `message.message` и primary `span` из JSON |
| Заменить нативные `Read`/`Bash`/`Edit` на AST-MCP | Отклонено | Обучение и навыки агентов привязаны к встроенным инструментам; AST уже закрывают LSP-серверы, а кастомный MCP ломается на логах, конфигах и `git` |
| Тяжёлый `PostToolUse`-демон после каждой правки | Отклонено | При правке N связанных файлов первые N-1 временно не собираются и порождают ложные ошибки; автоправка за спиной агента ломает следующий `Edit` |
| Запретить обычный текст в ответах | Опровергнуто цифрами | Текстовые ответы в чат дают около `1%` всех исходящих токенов |

## Скрытые утечки в конфигурации и инфраструктуре

При аудите окружения обнаружились пять проблем вне исходного кода:

1. **Пресеты Claude Desktop (`ccd-session-presets.json`) перебивают `settings.json`**. Десктопный клиент хранит модель и уровень усилий для каждого проекта отдельно и может открывать новые сессии на Opus или Fable вопреки глобальным настройкам CLI.
2. **Четыре перекрывающихся слоя проверок**. Глобальные хуки на все события (`*`), regex `Stop`-хуки, проверяющие формулировки текста («сказал "не проверил"»), тяжёлые команды на каждом `Stop` и локальные `.githooks`. Regex-блокировка ответа не ловит реальных багов в коде, но заставляет модель трижды прогонять весь контекст ради перефразирования. Надёжнее держать в `PreToolUse`/`PostToolUse` только быстрые детерминированные проверки (`< 20 ms`), а тесты запускать перед сдачей или коммитом.
3. **Более 20 глобальных плагинов и OpenAPI-MCP**. Описания инструментов каждого активного плагина и десятков эндпоинтов OpenAPI-MCP загружаются в каждый запрос. Глобально имеет смысл оставлять базовые 5-8 инструментов, подключая остальные точечно в `.claude/settings.json` проекта.
4. **Старые git worktree (`.claude/worktrees/`)**. Десятки забытых рабочих копий замедляют поиск и индексацию, поэтому их стоит регулярно удалять через `git worktree prune`.
5. **Отсутствие проекции `toMcp` в своих MCP**. Отправка сырых REST/UI-ответов (иконки, кнопки, история из 40+ записей) с отступами быстро съедает контекст без пользы для решения задачи.

Для любого харнеса (Claude Code, Antigravity или собственного агента) эффективнее всего работает пятиуровневый стек: настройка моделей и короткого `CLAUDE.md` (`ctxkit setup`), детерминированный `PreToolUse`-предохранитель на чтение и поиск, сжатие логов сборок и MCP (`ctxkit check` и `toMcp`), короткие сессии через `/clear` с батчингом инструментов (`Read`/`Edit`, `browser_batch`, `browser_snapshot` с `interactive_only: true` и `viewport_only: true`), а в собственных харнесах дополнительно Context Folding: сворачивание старых `tool_result` старше 6-8 ходов в одну строку статуса `[cmd #N -> OK / err]`.
