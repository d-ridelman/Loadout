# Политика безопасности

[English](SECURITY.md) · [Русский](SECURITY.ru.md)

## Как сообщить об уязвимости

Сообщайте об уязвимостях закрыто, через GitHub: откройте вкладку [Security](https://github.com/d-ridelman/Loadout/security) репозитория и нажмите **Report a vulnerability**. Не открывайте публичный issue о проблеме безопасности.

Укажите версию Loadout, клиент, шаги воспроизведения и что произошло. Не прикладывайте настоящие конфиги и бэкапы: в них могут быть токены. Имён ключей и записей достаточно.

## Поддерживаемые версии

Поддерживается только последний релиз. Исправления выходят новым релизом, старые версии не латаются.

| Версия | Поддержка |
|---|---|
| последний релиз | да |
| более ранние | нет |

## Что Loadout читает

- Конфиги пяти клиентов в вашем профиле Windows, в основном: `~/.claude.json`, `~/.claude/settings.json`, `~/.claude/plugins/installed_plugins.json` и `known_marketplaces.json`, `~/.claude/skills`, агенты и команды; `%APPDATA%\Claude\claude_desktop_config.json`; `~/.codex/config.toml`, `~/.codex/hooks.json`, `~/.codex/skills`; `~/.gemini/config/` (`mcp_config.json`, `hooks.json`, `plugins/`, `skills/`); `~/.dsh/cordis.patch.yml`, `~/.dsh/profiles/*/cordis.patch.yml`, `~/.dsh/skills`. А также кеши плагинов и папки встроенных скилов этих клиентов, каталоги (`marketplace.json`) добавленных маркетплейсов Claude Code и имена файлов-копий в папках клиентов (их считает Доктор).
- Значения `env` и заголовков MCP ядро держит у себя: окно, планы, журнал и сообщения об ошибках получают только имена ключей, остальные строки проходят маскировку (см. [docs/CONCEPT.md](docs/CONCEPT.md), §5). Файлы учётных данных клиентов (`~/.claude/.credentials.json`, `~/.codex/auth.json`, `~/.dsh/.credentials.yaml` и подобные) не читаются.
- Раздел «Инструменты контекста» запускает встроенный `context-toolkit.exe`. Он читает те же файлы Claude Code, а для отчёта «Эффективность» ещё и транскрипты Claude Code (`~/.claude/projects/**/*.jsonl`). В отчёте только счётчики, без текста и путей.

## Что Loadout пишет

На уровне R0 (по умолчанию) файлы клиентов не пишутся. Они меняются, только когда вы повысили уровень (R1 или R2, с подтверждением окном системы) и подтвердили предпросмотр. Свои данные Loadout (настройки, профили, очистка своих старых копий после подтверждения окном системы) пишет на любом уровне.

- **Конфиги клиентов**, только то значение, которое меняет операция (включить/выключить, корзина, правка, копия, добавление MCP, применение профиля).
- **`~/.claude/skills/<имя>`** при установке скила.
- **Плагины Claude Code** ставит сам CLI `claude` (`claude plugin marketplace add`, `claude plugin install`); окно сначала показывает точную команду.
- **Инструменты контекста** (`setup`, только по «Применить» или «Откатить»): `settings.json` и `CLAUDE.md` Claude Code, `~/.claude/hooks/context-toolkit.exe`, `~/.local/bin/context-toolkit.exe`, агенты `Explore` и `checker`, `context-toolkit.json`; с соответствующей галочкой также пресеты Claude Desktop, `hooks.json` Antigravity и файлы DeepSeek Harness.
- **Свои данные** в `%APPDATA%\loadout-app`: `settings.json` (язык и уровень записи), `backups\` (бэкапы операций с манифестами, по которым строится журнал, корзина, `profiles.json` и `staging\`, где скачанный скил ждёт вашего подтверждения) и служебные данные браузера Electron (настройка эффектов хранится в его local storage).

## В копиях есть секреты

Бэкапы операций и корзина хранят файлы клиентов **целиком и открытым текстом, включая значения `env` у MCP (ключи и токены)**: без них точный откат невозможен. Бэкапы Инструментов контекста (`~/.claude/backups` для Claude Code, рядом с изменяемым файлом у остальных клиентов) тоже содержат файлы целиком. Loadout их не шифрует и отдельных прав не задаёт: доступ такой же, как к вашему профилю Windows. Хранятся последние 100 операций не старше 90 дней; корзина сама не чистится. Как удалить данные: [README.ru.md](README.ru.md#установка).

## Сеть

У Loadout нет телеметрии, проверки обновлений и собственного сетевого кода. Сеть нужна только при явных действиях:

- установка плагина или добавление маркетплейса запускает `claude`, и тот скачивает из указанного вами источника;
- установка скила из GitHub запускает `git ls-remote` и `git clone` для указанного вами репозитория (из локальной папки скил ставится без сети).

## Какие процессы запускает Loadout

Окно запускает `loadout.exe` (ядро, из папки приложения), встроенный `context-toolkit.exe`, `tasklist` (чтобы предупредить, если запущен клиент, чей файл сейчас изменится), а при действиях выше ещё `claude` и `git` из `PATH`. Запускает без оболочки, с фиксированными флагами; аргументы из вашего ввода сначала проверяются (источник не может стать флагом или второй командой). Команды MCP-серверов из конфигов не запускаются никогда.

`context-toolkit.exe` запускает несколько процессов сам: `claude --version` через `cmd.exe` при предпросмотре (проверка версии Claude Code), `powershell.exe Get-Process` при галочке Claude Desktop (Desktop должен быть закрыт) и `--version` старого `ctxkit.exe` при переходе с прежней установки (чтобы убедиться, что файл наш, прежде чем удалить).

## Известные ограничения

- Установщик и приложение не подписаны.
- Секрет, записанный в описании скила обычными словами (не похожий на токен), не маскируется.
- Только Windows; приложение проверялось на Windows 11.
